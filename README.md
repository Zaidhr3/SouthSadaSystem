# نظام صدى الجنوب للمقاولات — South Sada Contracting ERP

نظام إدارة محلي متكامل لشركة **صدى الجنوب للمقاولات الإنشائية (مصنفة رابعة أبنية)** يعمل على جهاز/خادم الشركة.

**التقنيات:** Next.js 14 (App Router + Server Actions) · TypeScript · Prisma + SQLite · Tailwind CSS · Recharts · Nodemailer · ExcelJS

---

## النشر السحابي (Supabase + Cloudflare)

راجع **DEPLOYMENT.md** — الانتقال بأمر واحد: `npm run cloud:migrate` (ينقل كل البيانات ويتحقق منها). المزود (SQLite/PostgreSQL) يُضبط تلقائياً من `DATABASE_URL`.

## التشغيل

```powershell
npm install
copy .env.example .env      # ضع قيمة عشوائية طويلة في AUTH_SECRET
npm run setup               # إنشاء قاعدة البيانات — تبدأ فارغة تماماً (4 مستخدمين فقط)
npm run build
npm start                   # http://localhost:3000
```

| الأمر | الوظيفة |
|---|---|
| `npm run db:seed` | **يمسح كل البيانات والمرفقات** ويعيد الحسابات الأساسية فقط |
| `npm run db:demo` | يملأ النظام ببيانات تجريبية واقعية (2018–2026) للتدريب — **يمسح البيانات الحالية** |
| `npm run db:push` | تحديث جداول قاعدة البيانات بعد تعديل `schema.prisma` (وتفعيل RLS تلقائياً على Supabase) |

## التنبيهات البريدية (مجاناً)

1. **Gmail:** فعّل التحقق بخطوتين ← myaccount.google.com/apppasswords ← أنشئ «كلمة مرور تطبيق».
   **أو Brevo (300 رسالة يومياً مجاناً):** brevo.com ← SMTP & API ← أنشئ مفتاح SMTP.
2. أكمل في `.env`:
   ```
   SMTP_HOST="smtp.gmail.com"          # Brevo: smtp-relay.brevo.com
   SMTP_PORT="465"
   SMTP_USER="your.account@gmail.com"  # Brevo: بريد الدخول المعروض في لوحة SMTP
   SMTP_PASS="xxxx xxxx xxxx xxxx"     # كلمة مرور التطبيق / مفتاح SMTP
   SMTP_FROM="South Sada ERP <your.account@gmail.com>"
   APP_URL="http://192.168.1.10:3000"  # رابط النظام داخل الرسائل
   ALERT_INTERVAL_MINUTES="30"
   ```
3. أعد تشغيل الخادم، ثم من **المستخدمون** أضف بريد كل مستخدم، ومن **إعدادات النظام والبريد** اضغط «تشخيص البريد وإرسال رسالة اختبار».

> إذا ظهر `ETIMEDOUT` على المنفذ 587 فالشبكة تحجبه — استخدم `SMTP_PORT="465"` (اتصال SSL مباشر، يعمل مع Gmail وBrevo). هذا هو الإعداد الحالي على خادم الشركة.

**ما يُرسل:** الشيكات (قبل 3 أيام / اليوم / المتأخرة)، انتهاء الكفالات واسترداد كفالة الصيانة، مواعيد التقديم وزيارات المواقع، طلبات التمويل، أوامر التغيير ومستخلصات الباطن المعلقة، موعد استرداد المحجوزات، أوراق الشركة المنتهية — بالإضافة لإشعارات الأحداث (إسناد مشروع، اعتماد، قبض...).
كل تنبيه يُرسل **مرة واحدة لكل مرحلة** (سجل `EmailLog`)، ومجمّعة في رسالة واحدة لكل مستخدم.

**المجدول:** يعمل داخل الخادم كل `ALERT_INTERVAL_MINUTES`. بديل/إضافة: مهمة في Windows Task Scheduler تستدعي
`curl -H "x-cron-secret: <AUTH_SECRET>" http://localhost:3000/api/cron/alerts`

**أدوار الاطلاع فقط** (المشرف الأعلى والمراقب) محظورة من أي إنشاء أو تعديل أو حذف **على مستوى الخادم** (`actionUser` في `src/lib/auth.ts`) — ليس فقط بإخفاء الأزرار. المسموح لهما فقط: المراسلة الداخلية، تغيير كلمة المرور الشخصية، تأكيد الاطلاع على التعميم.
تُفرض الصلاحيات في كل صفحة وإجراء (`src/lib/permissions.ts`) وفي الوسيط (`src/middleware.ts`).

### التعاميم الإلزامية وإيقاف الحسابات
- **المستخدمون ← تعميم:** نص يظهر للمستخدم فور دخوله في نافذة لا تُغلق حتى يضغط «اطّلعت»؛ يظهر للمدير وقت الاطلاع، ويُسجل في سجل الرقابة.
- **المستخدمون ← إيقاف:** يُمنع الدخول فوراً (حتى الجلسات المفتوحة). عند محاولة الدخول بكلمة مرور صحيحة تظهر رسالة المدير، أو «الرجاء مراجعة إدارة الشركة» إن لم تُكتب رسالة.

### التطبيق على الهاتف (PWA)
افتح النظام عبر الرابط الآمن (https) ثم: **iPhone:** زر المشاركة ← «إضافة إلى الشاشة الرئيسية». **Android:** القائمة ← «تثبيت التطبيق». تظهر أيقونة شعار الشركة باسم «صدى الجنوب». الأيقونات في `public/icons/` ومولّدة من `public/logo.JPG` (يُفضّل استبدال الشعار بنسخة عالية الدقة 1024×1024 ثم إعادة توليدها).

## الوحدات

- **دورة حياة العطاء** — عشر مراحل من شراء الوثائق حتى الاستلام النهائي، مع تسلسل الكفالات التلقائي.
- **مساعد التسعير الذكي ومكتبة الأسعار** — أسعار كل بند عبر السنوات والسعر المقترح.
- **أوامر التغيير** — الاعتماد يعدّل قيمة العقد ومدته تلقائياً (وإلغاء الاعتماد يعكس الأثر).
- **مقاولو الباطن** — اتفاقيات، مستخلصات باسترداد تلقائي للدفعة المقدمة ومحجوزات، **منع تجاوز قيمة الاتفاقية**، دورة رفع ← اعتماد ← دفع.
- **المستودعات والمواد** — توريدات بصور إثبات ومقارنة بكميات جدول الكميات والاستهلاك النظري حسب الإنجاز، مع تنبيه الهدر.
- **الآليات والمعدات** — سجل المعدات المملوكة والمستأجرة؛ التشغيل يُحمّل الكلفة على المشروع (داخلياً للمملوكة، ومن البنك للمستأجرة).
- **الصادر والوارد** — ترقيم تلقائي `ص/2026/0001` و `و/2026/0001` مع نسخ PDF.
- **حاسبة المستقطعات** — المحجوزات (مع سقف من قيمة العقد) وضريبة الدخل المقتطعة ورسوم الطوابع؛ النسب من «إعدادات النظام». استرداد المحجوزات يُجدول مع كفالة الصيانة.
- **المطالبات المالية والفواتير** — معالج للمحاسب (`/claims/new`): يختار العطاء فتُجلب الكميات من حصر مدير المشروع، يراجع ويعدل النسب، ثم «إنشاء المطالبة والخلاصة». الحالات: مسودة ← مقدمة للتدقيق ← معتمدة ومقفلة (المدير العام) ← معتمدة من الجهة ← مسددة. لكل مطالبة مستند رسمي للطباعة/PDF مع التفقيط وكتل التواقيع، وملف Excel بثلاث أوراق مترابطة بمعادلات (الخلاصة، الأعمال المنجزة، الحصر). المطالبات اليدوية السابقة بلا كميات تُعالج بإدخال «الكميات السابقة» في أول مطالبة بالحصر لمنع تكرار المطالبة.
- **الضريبة** (`/taxes`) — منفصلة عن المطالبات: المديونية تُسجل عند قبض المطالبة (حسب النسبة في الإعدادات أو مبلغ يُدخل يدوياً) أو يدوياً، والسداد لدائرة الضريبة يُخصم من البنك. تذكير شهري بالبريد بالمديونية القائمة وإشعار فوري عند زيادتها. المطالبات لم تعد تخصم ضريبة الدخل ولا استرداد المقدمة.
- **المراسلات الداخلية** (`/messages`) — رسائل مباشرة بين المستخدمين مع ربط اختياري بعطاء، وحالة «تمت القراءة»، وإشعار فوري وبريد للمستلم.
- **سجل الرقابة والتدقيق** — كل إنشاء/تعديل/حذف يُلتقط تلقائياً على مستوى قاعدة البيانات (`src/lib/db.ts`) مع المستخدم والوقت، إضافة لتسجيلات الدخول والتصدير.
- **التصدير إلى Excel** — تقرير مشروع شامل (مع رؤى الأسعار التاريخية) وتقرير مالي لأي فترة.

## النسخ الاحتياطي

كل البيانات في `prisma/southsada.db` ومجلد `storage/uploads/` — انسخهما يومياً لقرص خارجي.

## دورة حياة المشروع التعاقدية (5 مراحل)

| المرحلة | المحتوى | من ينفّذها |
|---|---|---|
| 1. الإحالة والتعاقد | ورقة الإحالة + إيصال الطوابع (ملفان مستقلان) · أمر المباشرة + كفالة حسن التنفيذ (ملفان مستقلان) | المدير العام والمحاسب |
| 2. التنفيذ والحصر المرحلي | الإنجاز، الحصر الفعلي (X من Y بنداً)، المطالبات المرحلية — يراجعها المحاسب بالملاحظات والخصومات ويعتمدها المدير العام | مدير المشروع + المحاسب + المدير العام |
| 3. الاستلام الابتدائي | كشف اللجنة والنواقص ← معالجتها ← محضر الاستلام الابتدائي ومدة الصيانة سنة/سنتان | مدير المشروع / المحاسب / الإدارة |
| 4. المطالبة النهائية والكفالات | الحصر النهائي ← المطالبة النهائية · كفالة الصيانة (يصدرها المدير العام، يسلّمها مدير المشروع) مقابل كتاب الإفراج عن حسن التنفيذ | مدير المشروع + الإدارة |
| 5. الاستلام النهائي والإغلاق | كشف اللجنة ← محضر الاستلام النهائي ← قرار الإفراج عن كفالة الصيانة ← إغلاق المشروع | مدير المشروع / المحاسب / الإدارة |

**المرفقات اختيارية في كل المراحل** — تُحفظ البيانات وتنتقل المرحلة دون ملفات، وتُرفع لاحقاً من خانة كل مستند. النظام يمنع فقط التناقض في التواريخ (مثل استلام نهائي قبل الابتدائي) والتواريخ المستقبلية للمحاضر.

**المشاريع القديمة:** من «عطاء جديد» اختر «المرحلة الحالية» (من شراء الوثائق حتى «مغلق») وفعّل «عطاء قديم (أرشفة)» حتى لا تُنشأ مصاريف بأثر رجعي. ولأي مشروع قائم: زر «المرحلة والإسناد» (المدير العام) ينقله لأي مرحلة أو يعيد فتح مشروع مغلق.

القيود المالية تبقى للمحاسب والمدير العام: إصدار الكفالات من البنك وإعادتها، اعتماد المطالبات وقفلها، القبض والصرف، والحذف.
نسخة احتياطية كاملة قبل أي تعديل: `npm run db:backup` (تُحفظ في `backups/`).

**النسخ الاحتياطي التلقائي:** كل يوم مع مهمة التنبيهات (`/api/cron/alerts`) تُحفظ نسخة كاملة مضغوطة في حاوية خاصة `sada-backups` على Supabase Storage (`db/<التاريخ>.json.gz`)، والمرفقات تُنسخ مرة واحدة إلى `files/<رقم المرفق>`. الاحتفاظ: آخر 35 يوماً + نسخة لكل شهر لـ13 شهراً. يلزم `SUPABASE_SERVICE_ROLE_KEY` (سري) على الخادم. التنزيل والنسخ الفوري من «إعدادات النظام». اختبار: `npx tsx scripts/test-backup.ts`.

## دورة اعتماد المطالبات (المرحلية والنهائية)

1. **مدير المشروع:** يُدخل الحصر الفعلي (مرحلي أو نهائي) ← «إرسال المطالبة للمحاسب» — تُنشأ المطالبة تلقائياً.
2. **المحاسب:** يدقق الكميات والحسابات والخصومات ← «تدقيق ورفع للإدارة» (بريد رسمي للمدير العام)، أو يعيدها لمدير المشروع مع السبب.
3. **الإدارة:** «موافقة» ← **تمت الموافقة — بانتظار الصرف**، أو «رفض مع السبب» ← يُعاد الحصر لمدير المشروع ليعدّل ويعيد التقديم (بنفس رقم المطالبة).
4. **الصرف:** مدير المشروع/المحاسب/الإدارة يتابعون المراحل (سُلّمت ← لدى المهندس المشرف ← المالية ← صدر الشيك) ويبلغون عن أي **معيق**، ويسجّل المحاسب القبض (**تم الصرف**) فيُودع المبلغ بالبنك.

كل مطالبة فيها: مسار الدورة، **سجل زمني** لكل خطوة (مع أسباب الرفض)، و**مراسلات داخلية مرتبطة بها** لتوثيق المعيقات بين الإدارة والموقع والمحاسب.

### نموذج المطالبة: الحسومات وإعادة الإرسال وقراءة الأرقام
- **مدير المشروع** يفتح «إنشاء مطالبة» لمشاريعه فقط، ويدخل الكميات والحسم (نسبة % من قيمة المطالبة أو مبلغ ثابت) مع سببه، ثم «إرسال المطالبة للمحاسب». نسب المحجوزات والطوابع للمحاسب والإدارة فقط.
- **المحاسب** يراجع الحسم ويعدّله من «الملاحظات والحسومات» قبل الرفع للإدارة (يُسجّل في سجل المطالبة).
- **المطالبة المرفوضة** تفتح مباشرة في وضع التعديل الكامل (من الإشعار أو زر «تعديل المطالبة وإعادة الإرسال») مع سبب الرفض، وتعود بنفس رقمها إلى المحاسب ثم الإدارة. الحسم بالنسبة يُعاد احتسابه تلقائياً.
- **الأرقام**: تُقبل الأرقام العربية والإنجليزية وفواصل الآلاف والفاصلة العشرية العربية (1,250.75 أو ١٬٢٥٠٫٧٥)، والحساب لحظي: كمية الفترة = التراكمي − السابق، قيمة الفترة = كمية الفترة × السعر، القيمة التراكمية = التراكمي × السعر.

## النسخة 1.0 — الإطلاق التشغيلي

### المطالبة والفاتورة الضريبية كمعاملة واحدة
1. **مدير المشروع** يفتح «إنشاء مطالبة»: ثلاث شاشات متزامنة لحظياً — جدول الكميات (الكميات الفعلية) ← المطالبة (الخلاصة) ← الفاتورة الضريبية الرسمية — ثم «تم وإرسال للمحاسب».
2. **المحاسب**: «قبول وتدقيق» (ترفع المطالبة والفاتورة معاً للإدارة) أو «رفض / تعديل» مع الملاحظات.
3. **الإدارة** (المدير العام أو المشرف الأعلى أبو أحمد): «موافقة نهائية» ← تُرسل الفاتورة تلقائياً لنظام الفوترة الوطني (جفوتارا) ويُخزن UUID ورمز QR — أو «رفض مع السبب».
4. **الطباعة**: صفحة المطالبة تطبع المستخلص المفصل + الفاتورة المعتمدة (QR) معاً.
5. **القبض**: «تم صرف الشيك» (صورة الشيك/الحوالة إلزامية) ← المحاسب يدقق ← الإدارة توافق ← إيداع في حساب الشركة البنكي ونقل المطالبة إلى «الأرشيف».

### جفوتارا (نظام الفوترة الوطني)
- المفاتيح في متغيرات الخادم فقط: `JOFOTARA_CLIENT_ID` و`JOFOTARA_SECRET_KEY` (لا تُحفظ في الكود).
- من «إعدادات النظام»: الرقم الضريبي، رقم تسلسل مصدر الدخل، نوع الفاتورة (دخل / مبيعات 16%)، وتفعيل الإرسال.
- الفشل لا يضيع: يظهر السبب للمحاسب مع زر «إرسال واعتماد من الضريبة» لإعادة المحاولة بنفس رقم الفاتورة.

### الذكاء الاصطناعي (Google Gemini)
- `GEMINI_API_KEY` على الخادم فقط، و`GEMINI_MODEL` (الافتراضي `gemini-2.5-flash`) لتغيير النموذج.
- **جدول الكميات**: رفع PDF/صور/Excel ← استخراج رقم البند والوصف والوحدة والكمية والسعر والإجمالي مع رقم الصفحة والمرجع ← تحقق حسابي وعلامة للقراءة غير الواضحة ← مراجعة وتسعير بمقارنة الأسعار التاريخية (ونفس الجهة) ← اعتماد. لا تُفترض أي قيمة غير مكتوبة.
- تعديل مدير المشروع لوصف/كمية بند مستخرج يظهر بشارة حمراء للمحاسب والإدارة.
- **الفواتير**: «قراءة الفاتورة آلياً» تعبئ المبلغ والتاريخ والمورد والتصنيف والمشروع للمراجعة قبل الحفظ.
- كل عملية استخراج مسجلة (جدول `AiExtraction`). حد الملف 4 ميغابايت.

### الأمان والتشغيل
- قفل تلقائي بعد **دقيقتين** خمول (في المتصفح وعلى الخادم) مع تحذير قبل 15 ثانية، وتوثيقه في سجل التدقيق.
- حفظ تلقائي للمسودات على الجهاز واستعادتها بعد انقطاع التغطية أو القفل.
- حالة قراءة الإشعارات في قاعدة البيانات: فتح الصفحة المرتبطة يعلّم التنبيه مقروءاً فوراً.
- RLS على كل الجداول وسحب صلاحيات الواجهة العامة (حتى للجداول المستقبلية).
- فواتير المصاريف: الصورة إلزامية؛ الفاتورة الأقدم من 7 أيام بلا صورة تُحفظ بعلامة «للتحقيق».
- التفويض المؤقت (من «المستخدمون»): يعمل المفوَّض إليه بصلاحيات الغائب ويُوثَّق كل إجراء «نيابة عن».
- نافذة «بيانات العقد» السريعة، مستودع المواد الفائضة للتدوير، تقرير الربحية الختامي، ولوحة المجلس الأعلى.

### رفع الملفات الكبيرة (Direct Upload إلى Supabase Storage)

- حد Vercel ثابت 4.5 ميغابايت للطلب الواحد ولا يرفعه `bodySizeLimit` — لذلك أي نموذج مرفقاته أكبر من 4 ميغابايت يُرفع **مباشرة من المتصفح** إلى الحاوية الخاصة `sada-staging` (حتى 20 ميغابايت للملف، `NEXT_PUBLIC_MAX_STAGED_MB`)، ويصل للخادم **رمز التذكرة فقط**.
- الخادم يصدر «تذكرة رفع» (جدول `UploadTicket`) لمسار عشوائي صالحة 15 دقيقة؛ سياسات RLS على `storage.objects` ترفض أي كتابة/قراءة لمسار بلا تذكرة صالحة — لا يلزم مفتاح service role.
- عند الحفظ يسحب الخادم الملف من التخزين ويحفظه في المرفقات كالمعتاد ثم يحذفه من منطقة العبور. جدول الكميات يُقرأ بـ Gemini مباشرة (ما فوق 14 ميغابايت عبر Gemini Files API).
- التهيئة (مرة واحدة، آمنة للتكرار): `npm run storage:setup`. التنظيف التلقائي للملفات المتروكة مع مهمة `/api/cron/alerts`.

## الديون الخارجية (`/debts`)

- تسجيل أي دين على الشركة (بنك، شخص، شركة، شريك، مورد): أصل الدين، الفائدة (نسبة سنوية بسيطة أو مبلغ مقطوع)، العمولات، الضمانات (شيكات ضمان/كمبيالة/رهن)، والمشروع المرتبط — مع معاينة فورية للقسط والمستحق الكلي.
- جدول أقساط تلقائي (شهري، ربعي، نصف سنوي، سنوي، أو دفعة واحدة). السداد يُوزَّع على الأقساط الأقدم أولاً، ويقبل الجزئي والمبكر، ويُغلق الدين تلقائياً عند اكتماله.
- **إعادة الجدولة**: الأقساط المسددة تبقى، والمتبقي يُوزع على جدول جديد مع إمكانية رفع المستحق (فوائد تأخير) أو خفضه (خصم/إعفاء) مع ذكر السبب في سجل الدين.
- الترابط: الاستلام بإيداع ← وارد في الحساب البنكي (مع وصل الإيداع)، السداد بتحويل/شيك ← صادر؛ الأقساط القادمة تدخل في **التدفق النقدي المتوقع** وحالة السيولة؛ تنبيهات قبل 7 و3 أيام ويوم الاستحقاق والتأخر (بالبريد أيضاً)؛ ورقتا «الديون» و«سداد الديون» في التقرير المالي.
- الصلاحيات: الاطلاع للمدير العام والمشرف الأعلى والمحاسب والمراقب؛ التسجيل والسداد وإعادة الجدولة للمدير العام والمحاسب؛ حذف دين أو دفعة للمدير العام فقط.
- اختبار المحرك (داخل معاملة تُلغى بالكامل): `npx tsx scripts/test-loans.ts`

## وصل الإيداع البنكي

كل إيداع في حساب الشركة يقوم به غير الإدارة (مدير مشروع، محاسب، مدقق...) يتطلب صورة وصل الإيداع، ويُرفض على الخادم بدونها: قبض المطالبة بشيك، استرداد المحجوزات، الدفعة المقدمة، استلام دين، والحركة البنكية اليدوية الواردة. المدير العام والمشرف الأعلى معفيان (الحكم بالدور الأصلي — المفوَّض بصلاحيات المدير العام يبقى ملزماً). الوصل يظهر بجانب الحركة في كشف الحساب البنكي.

## وضع الصيانة والمعاينة

- `MAINTENANCE_MODE=1` على Vercel: كل الصفحات تعرض «النظام تحت الصيانة» (503) ولا تُنفذ أي عملية — يلزم إعادة النشر بعد تغيير المتغير.
- `MAINTENANCE_BYPASS` (سر ≥ 16 حرفاً): فتح `/?preview=<السر>` مرة واحدة يحفظ كوكي لمدة 30 يوماً يسمح لهذا الجهاز فقط بتجربة النظام الحقيقي أثناء الصيانة.
- للإطلاق: احذف `MAINTENANCE_MODE` (`vercel env rm MAINTENANCE_MODE production`) ثم `vercel deploy --prod`.


## الوحدات الجديدة (2026-11-17)

### طلبات التسعير من موقع الشركة (`/quotes`)
- نموذج «اطلب عرض سعر» في الموقع يرسل إلى `POST /api/public/rfq` (CORS لنطاق الموقع فقط: `WEBSITE_ORIGIN`).

- المسار: مدير المشروع الأقل انشغالاً (دراسة + سعر مقترح + مرفقات) ← المحاسب (قبول أو إرجاع بملاحظات) ← الإدارة (اعتماد نهائي مع إنشاء «مشروع خاص» تلقائياً، أو رفض).

### المشاريع الخاصة وبوابة العملاء
- `/tenders/new?kind=PRIVATE`: مشروع خاص (المالك، الرقم المرجعي، المخططات وجداول الكميات) بلا ثمن وثائق.
- `/tenders/[id]/portal`: حسابات العملاء (الإدارة)، خطة العمل بأوزان ونسب، المراسلات، مستندات التوقيع المتبادل (توقيع مرسوم + SHA-256 للمستند + الوقت والعنوان).
- بوابة العميل `/portal`: جلسة مستقلة تماماً (كوكي ومفتاح مختلفان)، كلمة مرور مؤقتة تُغيَّر عند أول دخول، يرى: الإنجاز، المدة المنقضية، التسليم المتوقع، خطة العمل، اليوميات وصورها، المراسلات، التواقيع. لا يرى أي بيانات مالية.

### الأرشفة (`lib/archive.ts`)
- أرشيف فترة الصيانة: تلقائياً عند قبض المطالبة النهائية + لا كفالة حسن تنفيذ قائمة (أو غير مطلوبة).
- الأرشيف النهائي: لا كفالة صيانة قائمة + انقضاء مدة الصيانة إن وُجدت. مقفل لكل الكتابة؛ الإعادة للمدير العام فقط (بصفته الأصلية، لا بالتفويض) مع سبب موثق.
- مصاريف الصيانة: فئة «أعمال صيانة — فترة الكفالة» على المشروع.
